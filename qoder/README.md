
# Qoder 赛道交付说明

> 赛题：Qoder（20 分）｜作品：用 Qoder 从零构建一个「seekdb × PowerContext」的 AI 记忆助手

## 1. 作品是什么

一个**单页教程站点**：`index.html`，主题是「用 Qoder 从零搭一个 AI 记忆助手」。

站点内容按赛题要求组织，覆盖三块：

| 要求                    | 站点章节      | 内容                                                                                                                                            |
| ----------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| seekdb 概念与上手       | 第 2 章       | 它是什么、起实例、建表灌数、全文 / 向量 / 混合检索三种查询写法、APPROXIMATE 的取舍、全文索引与分词器                                            |
| PowerContext 概念与上手 | 第 3 章       | Scope / Source / Memory / Artifact / 处理 的语义，三种接入方式（HTTP API、MCP、Python SDK），以及如何打开自动处理                               |
| 从零构建一个应用        | 第 1、4、5 章 | 先定义「采集→派生→检索→沉淀」四步闭环，再把 seekdb（数据面）与 PowerContext（记忆面）接起来，最后给出用 Qoder 执行闭环的具体提示词与验收自查 |

## 2. 为什么这个作品适合「效率学习者」

教程不是 API 清单，而是**一条可执行、可验证的工程路径**：
每一章都给出可直接粘贴运行的 SQL / Python / 提示词，并明确「怎样算做对了」：

- 检索质量用固定评测集的 Recall@10 / nDCG@10 衡量，而不是凭感觉；
- 记忆是否真的被用上，用「写入一条记忆 → 新会话提问 → 看是否召回」来验证；
- 性能迭代要求对比三种检索方案（纯向量 / 纯全文 / 混合）并留下对比表。

这些正是 Qoder 这类工具最容易做砸的地方——它能快速产出代码，但不会自动产出可信的结论，
教程把「可信的结论怎么来」写成了可执行步骤。

## 3. 如何发布到 Qoder Sites

站点是**零依赖的静态页面**（内联 CSS，无外部字体、无构建步骤、无网络请求），因此：

1. 在 Qoder Sites 新建站点，选择静态站点模板；
2. 把本目录的 `index.html` 作为站点首页上传（或把整个目录作为静态资源根目录）；
3. 发布后把站点地址填入测评平台的 Qoder 赛道提交入口。

若平台要求 `index.html` 之外的额外入口（例如 `README.md` 形式的说明），可用本目录的 `README.md`。

## 5. 备注

- 页面中的向量维度、文件路径、连接串均为**占位值**，已在页脚标注需按环境替换。
- 教程中引用的 seekdb / PowerContext 能力均来自各自项目文档；
