# 周边去哪儿：基于高德的地点推荐助手

## 适用场景

- 「我在杭州某地铁站，想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。」
- 「我在上海人民广场，附近有什么适合遛弯的公园？走路 10 分钟内。」
- 「帮我找附近评分高的川菜馆，走路能到的。」

## 使用的工具

只用高德 MCP Server 的这两项能力：

| 用途 | 工具 | 关键参数 |
|---|---|---|
| 地点搜索 | `maps_around_search` | `location`（起点经纬度，格式「经度,纬度」）、`keywords`（地点类型，如「咖啡馆」）、`radius`（搜索半径，单位米） |
| 步行路线 | `maps_direction_walking_by_coordinates` | `origin`（起点经纬度）、`destination`（候选地点经纬度） |

补充说明：
- 起点坐标由评测给定，**不要**自行调用 `maps_ip_location` 猜测位置。
- 若用户只给了地名而没有坐标，先用 `maps_geo` 把地名解析成坐标，再用上面的流程。
- 需要某个 POI 的详细信息（例如营业时间、评分）时用 `maps_search_detail`（参数 `id`）。

## 执行步骤

### 1. 理解需求

从用户的话里提取三件事，缺省要明确：

| 要素 | 说明 | 缺省处理 |
|---|---|---|
| 地点类型 | 「咖啡馆」「公园」「川菜馆」等 | 用户没说就按最常见的「餐饮与咖啡」理解，并在答案里说明 |
| 步行时间上限 | 「15 分钟内」「走路 10 分钟」 | 用户没说就取 15 分钟，并说明这是默认假设 |
| 推荐数量 | 「最多 3 家」 | 最多 3 个（本题上限），用户要更少就按用户的来 |

同时记住起点坐标。

### 2. 查地点

用 `maps_around_search` 以起点为中心搜索：

- `radius` 取一个覆盖步行上限的半径。步行 15 分钟按 80 米/分钟估算约 1200 米，取 **1500 米** 留出余量，再靠第 3 步的路线数据精确筛选。
- `keywords` 直接用第 1 步理解出的地点类型；如果搜不到，依次尝试同义词（例如「咖啡」→「咖啡馆」→「茶饮」），仍无结果再进入第 5 步。

### 3. 查步行路线并筛选

对第 2 步返回的候选地点，**逐个**调用 `maps_direction_walking_by_coordinates` 查从起点出发的步行路线。

筛选规则（硬性条件，不可放宽）：

1. 只保留路线查询返回的**步行耗时 ≤ 用户步行时间上限**的地点。
2. **步行时间必须来自路线查询结果**，不能用直线距离换算来替代；直线上近但步行绕远的地点要排除。
3. 若路线查询失败（返回为空或报错），该候选直接剔除，并在答案里说明「有候选地点无法获取步行路线」。

### 4. 排序

按步行耗时从短到长排序。用户说「优先近一点」时严格按耗时升序；用户表达了其他偏好（例如「优先安静的」「优先有停车位的」）时，在同等步行时间的前提下把符合偏好的排在前面，并在推荐理由里说明这个偏好是怎么判断的——**只能依据工具返回的数据**。

### 5. 生成回答

从符合条件的地点里取**最多 3 个**（不足就少给，不要凑数）。按下面格式输出：

```markdown
为你找到 2 个步行可达的<地点类型>：

1. **<地点名称>**
   - 地址：<地点地址>
   - 步行：约 <距离> 米 / <耗时>（来自步行路线查询）
   - 推荐理由：<一句话，说明它为什么符合你的需求>
2. **<地点名称>**
   - 地址：<地点地址>
   - 步行：约 <距离> 米 / <耗时>
   - 推荐理由：<一句话>

未核实信息：营业时间、排队情况、安静程度等本次查询未验证，如需请以到店实际为准。
```

回答要求：
- 每个地点都要有：名称、地址、预计步行距离与时间、推荐理由。
- 距离和耗时照抄路线查询结果里的数值，不要自己四舍五入到另一个量级。
- 只有一个地点时也用同样的结构，不要输出表格之外的散文。

### 6. 异常与不足的处理

| 情况 | 怎么回答 |
|---|---|
| 步行上限内不足 3 个 | 如实说明「步行 <N> 分钟内只找到 <M> 个符合要求的地点」，给出已找到的，并建议放宽时间或类型；**不要**用超过时间上限的地点凑数。 |
| 周边搜没有结果 | 说明「在起点周边 <半径> 米内没有搜到符合条件的<类型>」，建议换个类型或换起点。 |
| 路线查询失败 | 说明「路线查询失败，无法确认步行时间」，不要用直线距离顶替。 |
| 地点信息缺失 | 缺什么写什么，缺的部分标注「未核实」。 |

**绝对不要编造**：地点名称、地址、距离、耗时必须来自工具返回；营业状态、排队情况、安静程度、评分这类工具没给的信息一律标注「未核实」。

## 示例

**用户**：我在杭州某地铁站（120.15,30.28），想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。

**执行**：
1. `maps_around_search(location="120.15,30.28", keywords="咖啡馆", radius=1500)`
2. 对返回的每个候选调用 `maps_direction_walking_by_coordinates(origin="120.15,30.28", destination="<候选坐标>")`
3. 保留步行耗时 ≤ 15 分钟的，按耗时升序，取前 3 个

**输出**：按上面的列表格式给出，每个地点附上工具返回的距离与耗时，并在最后统一标注未核实信息。

## 边界

- 本 Skill 只做「提出需求 → 查询高德 → 返回推荐」一次，不做多轮记忆与跨城市经验迁移。
- 推荐结果是**从同一起点出发的独立备选**，不要把它们串成一条多站行程。
- 不要在 Skill 里写任何高德 API Key，运行环境由平台配置。
